El incidente de las 3:00 AM

De madrugada, un comercio recibe una avalancha de pagos PSE y un banco dispara sus rechazos. En una hora vas a detectar el fraude, contener el riesgo y prevenir que se repita — sobre datos PSE reales en escala y un flujo en tiempo real, con Coco escribiendo el SQL contigo.

⏱ 60 minutos 💳 PSE 🔐 Seguridad 🏛 Gobierno 🛠 Desarrollo ☁️ ~30M txns en S3 + feed en vivo

Estás viendo el Módulo A: ruta full-stack. Cada módulo es un lab completo de punta a punta.

SeguridadA1. Detectar — caza de fraude PSE

Descríbele a Coco qué buscas; debajo queda el SQL de referencia.

A1.1 · Pico de rechazos por banco

Pídele a Coco

"Por banco y hora, dame rechazos y % de rechazo sobre PSE_TRANSACTIONS."

SELECT banco, DATE_TRUNC('hour', ts) AS hora, COUNT(*) AS total,
       SUM(IFF(estado='RECHAZADA',1,0)) AS rechazos,
       ROUND(100*SUM(IFF(estado='RECHAZADA',1,0))/COUNT(*),1) AS pct_rechazo
FROM PSE_TRANSACTIONS GROUP BY 1,2 HAVING rechazos > 500 ORDER BY rechazos DESC;

Esperado: Scotiabank Colpatria a las 03:00, ~1.605 rechazos (57,3%).

A1.2 · Velocity por documento

SELECT documento_hash, TIME_SLICE(ts,10,'MINUTE') AS ventana, COUNT(*) AS txns
FROM PSE_TRANSACTIONS GROUP BY 1,2 HAVING COUNT(*) >= 15 ORDER BY txns DESC;

Esperado: anillo DOC900000xx, 20–25 txns en 10 minutos.

A1.3 · Monto atípico por comercio

WITH s AS (SELECT AVG(monto) mu, STDDEV(monto) sd FROM PSE_TRANSACTIONS)
SELECT comercio_id, COUNT(*) n, ROUND(MAX(monto)/1e6,1) max_mcop
FROM PSE_TRANSACTIONS, s WHERE monto > s.mu + 3*s.sd
GROUP BY 1 ORDER BY max_mcop DESC;

Esperado: comercio 9001 con hasta ~199 MCOP.

A1.4 · Comercio bajo ataque

SELECT comercio_id, TIME_SLICE(ts,10,'MINUTE') AS ventana, COUNT(*) AS txns,
       COUNT(DISTINCT documento_hash) AS documentos, ROUND(SUM(monto)/1e6,1) AS mcop
FROM PSE_TRANSACTIONS GROUP BY 1,2 HAVING COUNT(*) > 300 ORDER BY txns DESC;

Esperado: comercio 9001 domina las ventanas 03:00–03:20.

Conclusión: las 4 señales convergen en el comercio 9001 y el anillo DOC900000xx.

GobiernoA2. Contener — gobernar el dato sensible

-- Clasificacion automatica
SELECT SYSTEM$CLASSIFY('HOL_SEC.INCIDENTE.PSE_TRANSACTIONS', {'auto_tag': true});

-- Enmascarar documento
CREATE OR REPLACE MASKING POLICY mask_doc AS (val STRING) RETURNS STRING ->
  CASE WHEN CURRENT_ROLE() IN ('ACCOUNTADMIN','SECURITYADMIN') THEN val ELSE 'DOC-****' END;
ALTER TABLE PSE_TRANSACTIONS MODIFY COLUMN documento_hash SET MASKING POLICY mask_doc;

-- Acceso por fila por banco
CREATE OR REPLACE ROW ACCESS POLICY rap_banco AS (banco STRING) RETURNS BOOLEAN ->
  CASE WHEN CURRENT_ROLE() IN ('ACCOUNTADMIN','SECURITYADMIN') THEN TRUE
       WHEN CURRENT_ROLE() = 'ENTIDAD_BANCOLOMBIA' THEN banco = 'Bancolombia' ELSE FALSE END;
ALTER TABLE PSE_TRANSACTIONS ADD ROW ACCESS POLICY rap_banco ON (banco);

-- Triage de severidad con Cortex AI
SELECT comercio_id,
       AI_CLASSIFY('Comercio ' || comercio_id || ' con pico de transacciones y montos atipicos de madrugada',
                   ['critico','alto','medio','bajo']):labels[0]::STRING AS severidad
FROM (SELECT DISTINCT comercio_id FROM PSE_TRANSACTIONS WHERE monto > 80000000);

DesarrolloA3. Prevenir — tiempo real + dashboard en SPCS

Arquitectura: feeder → S3 pse_stream/ (cada ~15s) → Snowpipe auto-ingest → Dynamic Tables (lag 1 min) → dashboard. El instructor arranca el feeder.
-- PIPE con auto-ingest
CREATE OR REPLACE PIPE pse_pipe AUTO_INGEST = TRUE AS
COPY INTO PSE_TRANSACTIONS FROM @stg_hol/pse_stream/ FILE_FORMAT = (FORMAT_NAME = ff_csv_gz);
SHOW PIPES LIKE 'pse_pipe';   -- toma notification_channel (ARN de SQS)

-- Dynamic Tables
CREATE OR REPLACE DYNAMIC TABLE DT_PSE_POR_MINUTO TARGET_LAG='1 minute' WAREHOUSE=HOL_WH AS
SELECT DATE_TRUNC('minute',ts) minuto, banco, estado, COUNT(*) txns, SUM(monto) monto_total
FROM PSE_TRANSACTIONS GROUP BY 1,2,3;
CREATE OR REPLACE DYNAMIC TABLE DT_PSE_RECHAZOS TARGET_LAG='1 minute' WAREHOUSE=HOL_WH AS
SELECT DATE_TRUNC('hour',ts) hora, banco, COUNT(*) total,
       SUM(IFF(estado='RECHAZADA',1,0)) rechazos,
       ROUND(100*SUM(IFF(estado='RECHAZADA',1,0))/COUNT(*),1) pct_rechazo
FROM PSE_TRANSACTIONS GROUP BY 1,2;
CREATE OR REPLACE DYNAMIC TABLE DT_PSE_COMERCIO_ATAQUE TARGET_LAG='1 minute' WAREHOUSE=HOL_WH AS
SELECT comercio_id, TIME_SLICE(ts,10,'MINUTE') ventana, COUNT(*) txns, SUM(monto) monto_total
FROM PSE_TRANSACTIONS GROUP BY 1,2;

Configura la notificación del bucket hacia el notification_channel del pipe (una vez, del lado AWS):

aws s3api put-bucket-notification-configuration --bucket demosjparrado \
  --notification-configuration '{"QueueConfigurations":[{
    "QueueArn":"<NOTIFICATION_CHANNEL_ARN>","Events":["s3:ObjectCreated:*"],
    "Filter":{"Key":{"FilterRules":[{"Name":"prefix","Value":"hol_ach_2/pse_stream/"}]}}}]}'
