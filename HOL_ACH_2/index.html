El incidente de las 3:00 AM

De madrugada, un comercio recibe una avalancha de pagos PSE y un banco dispara sus rechazos. En una hora vas a detectar el fraude, contener el riesgo y prevenir que se repita — sobre ~30M de transacciones PSE cargadas desde S3, con Coco escribiendo el SQL contigo.

⏱ 60 minutos 💳 PSE 🔐 Seguridad 🏛 Gobierno 🛠 Desarrollo ☁️ ~30M txns en S3 (batch)

Estás viendo la Opción 1: ruta full-stack. Cada opción es un lab completo de punta a punta.

Opción 1 · Full-stack

Requisitos: Coco Desktop, Node.js, Snowflake CLI (snow) y Podman. Usas Coco para escribir el SQL, el CLI para operar y, en el Módulo 4, contenerizas y despliegas el dashboard en SPCS.

  • 00–06Módulo 1 · Setup — entorno + carga del histórico PSE desde S3.
  • 06–24SeguridadMódulo 2 · Detectar (4 señales de fraude PSE).
  • 24–42GobiernoMódulo 3 · Contener (clasificar, enmascarar, acceso por banco).
  • 42–56DesarrolloMódulo 4 · Capa semántica, agente y app React en SPCS.
  • 56–60Módulo 5 · Cierre y limpieza.

Módulo 1. Setup — entorno y carga del histórico PSE

En Coco Desktop abre una worksheet (o usa snow sql) y ejecuta el bloque. Reemplaza las credenciales que te da el instructor.

CREATE DATABASE IF NOT EXISTS HOL_SEC;
CREATE SCHEMA IF NOT EXISTS HOL_SEC.INCIDENTE;
CREATE WAREHOUSE IF NOT EXISTS HOL_WH
  WAREHOUSE_SIZE = XSMALL AUTO_SUSPEND = 60 AUTO_RESUME = TRUE;

USE SCHEMA HOL_SEC.INCIDENTE;
USE WAREHOUSE HOL_WH;

CREATE OR REPLACE FILE FORMAT ff_csv_gz
  TYPE = CSV FIELD_DELIMITER = ';' SKIP_HEADER = 1
  FIELD_OPTIONALLY_ENCLOSED_BY = '"' COMPRESSION = GZIP;

CREATE OR REPLACE STAGE stg_hol
  URL = 's3://demosjparrado/hol_ach_2/'
  CREDENTIALS = (AWS_KEY_ID = '<AWS_KEY_ID>' AWS_SECRET_KEY = '<AWS_SECRET_KEY>')
  FILE_FORMAT = ff_csv_gz;

CREATE OR REPLACE TABLE PSE_TRANSACTIONS (
  txn_id NUMBER PRIMARY KEY, ts TIMESTAMP_NTZ, banco STRING, comercio_id NUMBER,
  monto NUMBER, canal STRING, estado STRING, tipo_persona STRING,
  documento_hash STRING, ciudad STRING,
  nombre STRING, email STRING, telefono STRING);
CREATE OR REPLACE TABLE COMERCIOS (comercio_id NUMBER PRIMARY KEY, nombre STRING, categoria STRING);
CREATE OR REPLACE TABLE BANCOS (banco STRING PRIMARY KEY, tipo STRING);

-- Relaciones (FK informativas): habilitan que el modelo semantico infiera los joins
ALTER TABLE PSE_TRANSACTIONS ADD FOREIGN KEY (banco)       REFERENCES BANCOS (banco);
ALTER TABLE PSE_TRANSACTIONS ADD FOREIGN KEY (comercio_id) REFERENCES COMERCIOS (comercio_id);

-- Carga por lotes (batch) desde S3 — sin INSERT, todo viene del bucket
COPY INTO PSE_TRANSACTIONS FROM @stg_hol/pse_hist/;
COPY INTO COMERCIOS        FROM @stg_hol/comercios/;
COPY INTO BANCOS           FROM @stg_hol/bancos/;
SELECT COUNT(*) AS transacciones FROM PSE_TRANSACTIONS;  -- ~30.003.515

SeguridadMódulo 2. Detectar — caza de fraude PSE

Descríbele a Coco qué buscas; debajo queda el SQL de referencia.

Módulo 2.1 · Pico de rechazos por banco

Pídele a Coco

"Por banco y hora, dame rechazos y % de rechazo sobre PSE_TRANSACTIONS."

SELECT banco, DATE_TRUNC('hour', ts) AS hora, COUNT(*) AS total,
       SUM(IFF(estado='RECHAZADA',1,0)) AS rechazos,
       ROUND(100*SUM(IFF(estado='RECHAZADA',1,0))/COUNT(*),1) AS pct_rechazo
FROM PSE_TRANSACTIONS GROUP BY 1,2 HAVING rechazos > 500 ORDER BY rechazos DESC;

Esperado: Scotiabank Colpatria a las 03:00, ~1.605 rechazos (57,3%).

Módulo 2.2 · Velocity por documento

SELECT documento_hash, TIME_SLICE(ts,10,'MINUTE') AS ventana, COUNT(*) AS txns
FROM PSE_TRANSACTIONS GROUP BY 1,2 HAVING COUNT(*) >= 15 ORDER BY txns DESC;

Esperado: anillo DOC900000xx, 20–25 txns en 10 minutos.

Módulo 2.3 · Monto atípico por comercio

WITH s AS (SELECT AVG(monto) mu, STDDEV(monto) sd FROM PSE_TRANSACTIONS)
SELECT comercio_id, COUNT(*) n, ROUND(MAX(monto)/1e6,1) max_mcop
FROM PSE_TRANSACTIONS, s WHERE monto > s.mu + 3*s.sd
GROUP BY 1 ORDER BY max_mcop DESC;

Esperado: comercio 9001 con hasta ~199 MCOP.

Módulo 2.4 · Comercio bajo ataque

SELECT comercio_id, TIME_SLICE(ts,10,'MINUTE') AS ventana, COUNT(*) AS txns,
       COUNT(DISTINCT documento_hash) AS documentos, ROUND(SUM(monto)/1e6,1) AS mcop
FROM PSE_TRANSACTIONS GROUP BY 1,2 HAVING COUNT(*) > 300 ORDER BY txns DESC;

Esperado: comercio 9001 domina las ventanas 03:00–03:20.

Conclusión: las 4 señales convergen en el comercio 9001 y el anillo DOC900000xx.

GobiernoMódulo 3. Contener — gobernar el dato sensible

-- Clasificacion automatica de PII: descubre y taggea columnas sensibles
-- (detecta EMAIL con confianza alta y le aplica semantic_category=EMAIL, privacy_category=IDENTIFIER)
CALL SYSTEM$CLASSIFY('HOL_SEC.INCIDENTE.PSE_TRANSACTIONS', {'auto_tag': true});

-- Ver los tags que aplico la clasificacion (semantic_category / privacy_category)
SELECT column_name, tag_name, tag_value
FROM TABLE(INFORMATION_SCHEMA.TAG_REFERENCES_ALL_COLUMNS('PSE_TRANSACTIONS','table'))
ORDER BY 1;

-- Enmascarar el email detectado (IDENTIFIER) y demas datos personales (documento, nombre)
CREATE OR REPLACE MASKING POLICY mask_pii AS (val STRING) RETURNS STRING ->
  CASE WHEN CURRENT_ROLE() IN ('ACCOUNTADMIN','SECURITYADMIN') THEN val ELSE '***-REDACTED' END;
ALTER TABLE PSE_TRANSACTIONS MODIFY COLUMN documento_hash SET MASKING POLICY mask_pii;
ALTER TABLE PSE_TRANSACTIONS MODIFY COLUMN email          SET MASKING POLICY mask_pii;
ALTER TABLE PSE_TRANSACTIONS MODIFY COLUMN nombre         SET MASKING POLICY mask_pii;

-- Acceso por fila por banco
CREATE OR REPLACE ROW ACCESS POLICY rap_banco AS (banco STRING) RETURNS BOOLEAN ->
  CASE WHEN CURRENT_ROLE() IN ('ACCOUNTADMIN','SECURITYADMIN') THEN TRUE
       WHEN CURRENT_ROLE() = 'ENTIDAD_BANCOLOMBIA' THEN banco = 'Bancolombia' ELSE FALSE END;
ALTER TABLE PSE_TRANSACTIONS ADD ROW ACCESS POLICY rap_banco ON (banco);

-- Triage del incidente con Cortex AI: resumen + accion recomendada (lenguaje natural)
-- Nota: si 'claude-4-sonnet' no esta disponible en tu region, usa p.ej. 'llama3.1-70b' o habilita cross-region inference.
WITH w AS (
  SELECT TIME_SLICE(ts,10,'MINUTE') AS ventana, COUNT(*) AS txns,
         COUNT(DISTINCT documento_hash) AS documentos, ROUND(SUM(monto)/1e6,0) AS monto_mcop
  FROM PSE_TRANSACTIONS WHERE comercio_id = 9001 GROUP BY 1
),
peak AS (SELECT * FROM w ORDER BY txns DESC LIMIT 1)
SELECT AI_COMPLETE('claude-4-sonnet',
  'Eres analista antifraude de PSE. En 1-2 frases indica la severidad (critico/alto/medio/bajo) y la accion recomendada. ' ||
  'Alerta: el comercio 9001 recibio ' || txns || ' transacciones de ' || documentos ||
  ' documentos distintos por ' || monto_mcop || ' millones COP en una ventana de 10 minutos (' || ventana || ').') AS triage
FROM peak;
Pídele a Coco

"¿Qué vistas, tablas dinámicas o dashboards dependen de PSE_TRANSACTIONS? Antes de bloquear el comercio, dime qué se rompería." (skill lineage)

Módulo 4.1 · Capa semántica (en Snowsight, por UI)
